Astro Starlight Tags Categories and Filtering

A practical tutorial for adding tags, categories, difficulty levels, regions, factions, and filtering pages to an Astro Starlight project.

What You Are Building

This tutorial shows how to organize a growing Astro Starlight site with tags, categories, and filtered index pages.

You will learn how to create:

  • Tag fields in frontmatter.
  • Category and level fields in schemas.
  • Filtered lesson indexes.
  • Filtered world bible indexes.
  • Tag landing pages.
  • Category pages for lessons, characters, regions, factions, and topics.

Big Picture Mental Model

Tags and categories are labels that help readers find related content.

Content page
  ↓
Frontmatter metadata
  ↓
Collection schema
  ↓
Filtering and sorting
  ↓
Index pages, tag pages, category pages, related links

Think of tags like sticky notes and categories like shelves. A book usually belongs on one main shelf, but it can have many sticky notes.

Tags vs Categories

Concept Meaning Example
Category A primary grouping. Beginner, Intermediate, Advanced
Tag A flexible label that can apply across groups. markdown, deployment, worldbuilding
Type The kind of entry. lesson, character, region, faction
Status The state of the entry. draft, active, archived

Create a Content Collection Schema

Create or edit:

src/content.config.ts

Add a lesson collection:

import { defineCollection, z } from 'astro:content';

const lessons = defineCollection({
  schema: z.object({
    title: z.string(),
    description: z.string(),
    type: z.literal('lesson'),
    category: z.string(),
    level: z.enum(['beginner', 'intermediate', 'advanced']),
    order: z.number().default(999),
    draft: z.boolean().default(false),
    tags: z.array(z.string()).default([]),
  }),
});

export const collections = {
  lessons,
};

This ensures all lesson entries use consistent metadata.

Add a World Bible Collection

import { defineCollection, z } from 'astro:content';

const world = defineCollection({
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    type: z.enum(['region', 'character', 'faction', 'location', 'storyline', 'reference']),
    category: z.string(),
    region: z.string().optional(),
    faction: z.string().optional(),
    status: z.enum(['active', 'draft', 'archived', 'unknown']).default('active'),
    tags: z.array(z.string()).default([]),
  }),
});

export const collections = {
  world,
};

For a large project, separate collections such as characters, regions, and factions may be better. For a smaller project, one world collection can be enough.

Folder Structure for Collection-Based Content

A collection-based lesson system might look like this:

src/content/
  lessons/
    markdown-basics.md
    yaml-basics.md
    content-collections.md

A collection-based world bible might look like this:

src/content/
  world/
    regions/europe.md
    regions/austral-confluence.md
    characters/example-character.md
    factions/example-faction.md

Starlight's normal docs pages live in src/content/docs/. Custom collection pages can be rendered with Astro pages under src/pages/.

Read and Filter a Collection

Use getCollection() in an Astro page.

---
import { getCollection } from 'astro:content';

const lessons = await getCollection('lessons', ({ data }) => {
  return data.draft !== true;
});

const beginnerLessons = lessons.filter((lesson) => {
  return lesson.data.level === 'beginner';
});

const sortedLessons = beginnerLessons.sort((a, b) => {
  return a.data.order - b.data.order;
});
---

<h1>Beginner Lessons</h1>

<ul>
  {sortedLessons.map((lesson) => (
    <li>{lesson.data.title}</li>
  ))}
</ul>

Create a Beginner Lessons Index

Create:

src/pages/lessons/beginner.astro

Add:

---
import { getCollection } from 'astro:content';

const lessons = await getCollection('lessons', ({ data }) => {
  return data.level === 'beginner' && data.draft !== true;
});

lessons.sort((a, b) => a.data.order - b.data.order);
---

<html lang="en">
  <head>
    <title>Beginner Lessons</title>
  </head>
  <body>
    <h1>Beginner Lessons</h1>
    <ul>
      {lessons.map((lesson) => (
        <li>
          <a href={`/lessons/${lesson.id}/`}>{lesson.data.title}</a>
          <p>{lesson.data.description}</p>
        </li>
      ))}
    </ul>
  </body>
</html>

This is a simple Astro page, not a Starlight docs page. You can later wrap it in a layout to make it match the rest of the site.

Generate Lesson Pages from a Collection

Create:

src/pages/lessons/[...slug].astro

Add:

---
import { getCollection, render } from 'astro:content';

export async function getStaticPaths() {
  const lessons = await getCollection('lessons', ({ data }) => data.draft !== true);

  return lessons.map((lesson) => ({
    params: { slug: lesson.id },
    props: { lesson },
  }));
}

const { lesson } = Astro.props;
const { Content } = await render(lesson);
---

<article>
  <h1>{lesson.data.title}</h1>
  <p>{lesson.data.description}</p>
  <Content />
</article>

Find All Tags

To build a tag index, collect every tag from every entry.

---
import { getCollection } from 'astro:content';

const lessons = await getCollection('lessons', ({ data }) => data.draft !== true);

const tagSet = new Set();

for (const lesson of lessons) {
  for (const tag of lesson.data.tags) {
    tagSet.add(tag);
  }
}

const tags = Array.from(tagSet).sort();
---

<h1>Tags</h1>

<ul>
  {tags.map((tag) => (
    <li><a href={`/tags/${tag}/`}>{tag}</a></li>
  ))}
</ul>

Create Dynamic Tag Pages

Create:

src/pages/tags/[tag].astro

Add:

---
import { getCollection } from 'astro:content';

export async function getStaticPaths() {
  const lessons = await getCollection('lessons', ({ data }) => data.draft !== true);
  const tagSet = new Set();

  for (const lesson of lessons) {
    for (const tag of lesson.data.tags) {
      tagSet.add(tag);
    }
  }

  return Array.from(tagSet).map((tag) => ({
    params: { tag },
  }));
}

const { tag } = Astro.params;
const lessons = await getCollection('lessons', ({ data }) => {
  return data.draft !== true && data.tags.includes(tag);
});
---

<h1>Tag: {tag}</h1>

<ul>
  {lessons.map((lesson) => (
    <li>
      <a href={`/lessons/${lesson.id}/`}>{lesson.data.title}</a>
      <p>{lesson.data.description}</p>
    </li>
  ))}
</ul>

Create Category Pages

Categories work like tags, but each page usually has one main category.

---
import { getCollection } from 'astro:content';

export async function getStaticPaths() {
  const lessons = await getCollection('lessons');
  const categories = new Set(lessons.map((lesson) => lesson.data.category));

  return Array.from(categories).map((category) => ({
    params: { category },
  }));
}

const { category } = Astro.params;
const lessons = await getCollection('lessons', ({ data }) => {
  return data.category === category && data.draft !== true;
});
---

<h1>Category: {category}</h1>

<ul>
  {lessons.map((lesson) => (
    <li>{lesson.data.title}</li>
  ))}
</ul>

World Bible Filtering Examples

Filter by type:

const characters = await getCollection('world', ({ data }) => {
  return data.type === 'character' && data.status !== 'draft';
});

Filter by region:

const europeEntries = await getCollection('world', ({ data }) => {
  return data.region === 'Europe' && data.status !== 'draft';
});

Filter by faction:

const factionEntries = await getCollection('world', ({ data }) => {
  return data.faction === 'House Miraculo';
});

Create Related Content

Related content can be found by matching tags.

const currentTags = entry.data.tags;

const related = allEntries.filter((candidate) => {
  if (candidate.id === entry.id) return false;
  return candidate.data.tags.some((tag) => currentTags.includes(tag));
});

This works well for related lessons, characters in the same region, factions connected by theme, or reference pages that share a topic.

Filtering Strategy for Starlight Docs Pages

Starlight documentation pages can use frontmatter and sidebar controls, but generated filtering pages are usually easiest to build with Astro pages and content collections.

A good pattern is:

src/content/docs/
  normal Starlight documentation pages

src/content/lessons/
  structured collection entries

src/pages/tags/[tag].astro
  generated tag pages

src/pages/categories/[category].astro
  generated category pages

This keeps Starlight good at documentation while letting Astro handle generated indexes and filtered pages.

Common Mistakes

Too many tags

If every page has ten tags, the tag system becomes noisy. Use the few tags that are truly useful.

Inconsistent spelling

Bad:
content collection
content-collection
content-collections
Content Collections

Pick one version and reuse it.

Using categories as tags

If every lesson has beginner, intermediate, or advanced, that should probably be a level field, not only a tag.

Forgetting to filter drafts

If you use draft: true, make sure public indexes exclude drafts.

Best Practices

  • Use categories for primary organization.
  • Use tags for cross-links and related topics.
  • Use enums for controlled fields such as level, type, status, and difficulty.
  • Use lowercase hyphenated tags.
  • Create tag pages only when tags help readers navigate.
  • Filter out drafts from public pages.
  • Sort lessons by order, and sort reference entries alphabetically.
  • Use related-content blocks sparingly.

Use tags for cross-links.
Use schemas for consistency.
Use filtered indexes for navigation.
